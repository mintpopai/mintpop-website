# mintpop-website 中英文 i18n 设计

日期：2026-07-03
状态：已与用户对齐（方案 A 获认可）

## 目标

官网支持简体中文与英文两套内容：中文页面可被搜索引擎收录、可直接分享；英文既有 URL 不变；不引入运行时 SSR，维持 vite-ssg 预渲染 + nginx 纯静态部署。

## 已确认的需求决策

| 决策点       | 结论                                                                                                  |
| ------------ | ----------------------------------------------------------------------------------------------------- |
| URL 策略     | 英文在根（`/`、`/legal`…），中文加 `/zh` 前缀（`/zh/`、`/zh/legal`…），两套均预渲染并互挂 hreflang    |
| 首访语言     | 不按浏览器语言自动跳转，只提供切换入口                                                                |
| 偏好记忆     | 手动切换后写 localStorage；回访时若打开的是另一语言页，客户端挂载后 `router.replace` 到偏好语言对等页 |
| 中文文案来源 | 由实现者翻译（含 SEO title/description），用户发布前校对                                              |
| 技术选型     | 方案 A：vue-i18n（intlify 官方，`legacy: false`）+ 双路由树生成                                       |

### 备选方案及否决理由

- 方案 B（零依赖自研 `t()` composable）：重造轮子（插值/复数等要自建），违背「偏好标准解法」的既定偏好。
- 方案 C（可选参数路由 `/:locale(zh)?/...`）：vite-ssg 不自动枚举动态参数路由，需手写 `includedRoutes`，路由↔SEO 契约测试复杂化。

## 架构

语言由 **URL 路径唯一决定**，是贯穿全部模块的单一原则：

```
URL 路径 (/zh 前缀有无)
   └─> 路由 meta.locale ('en' | 'zh')
         ├─> router 守卫设置 i18n.global.locale  → 组件文案
         └─> useSeo 按 locale 输出 head           → title/meta/hreflang/lang
```

SSG 构建期逐路由渲染时同样经过守卫，构建产物与运行时行为一致，无水合错配。locale 初始化不读 localStorage（避免重蹈主题水合的坑，见 `2026-06-27-seo-ssg-design.md`）。

### Locale 常量

`src/config/locale.ts`（或并入 site.ts，实现时定）：

- 成员名 SCREAMING_SNAKE_CASE（`EN` / `ZH`），**取值为小写 BCP-47 码 `'en'` / `'zh'`**。
- 与全局枚举规范的偏差已获用户知情认可：locale 码要进 URL、`<html lang>`、vue-i18n API，均为外部标准要求小写，按「技术符号例外」处理，代码注释注明。

## 模块设计

### 1. 路由（`src/router/index.ts`）

- 保留一份 **base 路由表**（path + name + 组件 + 是否进中文树），由生成函数产出两棵树：
  - 英文树：路径与 name 均沿用现状（`HOME`、`LEGAL`…）。
  - 中文树：路径加 `/zh` 前缀（首页路由 path 为 `/zh`，不带尾斜杠；SSG 产出 `dist/zh/index.html`，浏览器访问 `/zh/` 由 nginx 目录 index 命中），name 加 `_ZH` 后缀（`HOME_ZH`…）。
  - 每条路由挂 `meta.locale`。
- `/404` 只保留英文一条（不生成 `/zh/404`）：nginx `error_page` 只能指向一个文件。404 页文案双语同屏（英文为主 + 中文一行）。catch-all 路由维持现状。
- `scrollBehavior` 不变。

### 2. i18n 装配（`src/main.ts` + `src/locales/`）

- `createI18n({ legacy: false, locale: Locale.EN, fallbackLocale: Locale.EN, messages })`，在 ViteSSG setup 回调里 `app.use(i18n)` 并注册 router 守卫：`to.meta.locale` → `i18n.global.locale.value`。
- 词条文件：
  - `src/locales/en.ts` —— 真相源，`as const` 风格的嵌套 TS 对象。
  - `src/locales/zh.ts` —— 类型约束为与 en 同构（`MessageSchema = typeof en`），漏译编译报错。
- 两语言静态打包，不做懒加载（全站文案量小，YAGNI）。
- 组件内使用 `useI18n()` 的 `t()`；所有硬编码英文文案（Hero、Capabilities、Modalities、Header、Footer、占位页、404）抽为词条。

### 3. 语言切换器（`AppHeader.vue`）

- 现静态 `EN` 徽标替换为**链接式切换器**：RouterLink 指向当前页在另一语言下的对等路径（由当前路径去掉/加上 `/zh` 前缀计算，锚点 hash 保留）。链接可被爬虫发现，是中文页的站内入口。
- 点击时写 `localStorage('mint-locale')`。
- 偏好回跳：`App.vue` 的 `onMounted`（仅客户端）读取偏好，若与当前页 locale 不同且对等页存在，`router.replace` 过去。首访无偏好不动作。

### 4. SEO / head（`src/config/seo.ts` + `src/composables/useSeo.ts`）

- `SEO` 结构改为按语言存文案：每个路由 key 含 `path`（英文路径，单一来源）+ 各语言 `{ title, description }`；中文路径由 `path` 派生（`/zh` 前缀）。`noindex` 标志语言无关。
- `useSeo(key)` 从当前路由取 locale，输出：
  - 本地化 `title`、`description`；
  - `og:locale`：`en_US` / `zh_CN`；`og:title` 等同步本地化；
  - `canonical` 指向**本语言**绝对 URL；
  - hreflang alternate：`en`、`zh` 与 `x-default`（指英文）三条 `<link rel="alternate" hreflang>`；noindex 页不输出 hreflang；
  - `htmlAttrs: { lang }`：`en` / `zh-CN`（unhead 在 SSG 时写入预渲染 HTML）。
- 首页 JSON-LD 的 description 跟随语言。
- sitemap（`vite.config.ts onFinished`）：从 SEO 配置派生，把两种语言的可收录页全部列入（`INDEXABLE_ROUTES` 派生逻辑同步扩展）。
- `index.html` 静态 `<title>`/description 保留英文作无 JS 兜底，不变。

### 5. 中文字体（`src/styles/theme.css`）

- 不自托管中文 webfont（体积 MB 级、不划算）；在字体栈补 CJK 系统字体回退：`PingFang SC`（macOS/iOS）、`Microsoft YaHei`（Windows）、`Noto Sans CJK SC`（Linux/Android）。拉丁字符仍由 Space Grotesk / Newsreader 渲染。

### 6. 错误处理

- 未知路径：行为不变（nginx 真 404 + 预渲染 404 页；客户端 catch-all 渲染 404 视图）。`/zh/不存在` 同样落入 catch-all。
- 词条缺失：编译期由 `MessageSchema` 同构约束拦截；运行期 `fallbackLocale: 'en'` 兜底显示英文而非空白。
- 偏好回跳只在对等路由确实存在时执行，避免 replace 到 404。

### 7. 测试

- **路由↔SEO 契约测试**扩展：
  - 每个命名路由（两棵树）都有对应 SEO 文案且 path 一致；
  - 中文树 path == `/zh` + 英文树 path（首页特例：英文 `/` 对应中文 `/zh`）；
  - sitemap 派生的路径都在路由表内。
- **词条完整性**：`zh` 与 `en` 的扁平化 key 集合完全一致（类型已挡，测试作运行时守护，防 `any` 逃逸）。
- **切换器路径计算**：纯函数单测（`/legal` ↔ `/zh/legal`、`/` ↔ `/zh`、带 hash 保留）。
- 构建冒烟：`mise run build` 后确认 `dist/zh/index.html` 等中文页存在（可作为 CI 现有 build 步骤的自然产物核查，不强制新增脚本）。

## 明确不做（YAGNI）

- 不做浏览器语言自动跳转；不做 cookie/服务端协商。
- 不做词条懒加载、不引入 `@intlify/unplugin-vue-i18n` 构建插件（词条量小，TS 对象足够；vue-i18n 自带编译器体积代价可接受）。
- 不自托管中文字体。
- 不预渲染 `/zh/404`。
- 不改 nginx 配置（`/zh/` 目录天然被 `try_files $uri $uri/` 覆盖）。
